# 数据接入与来源约定

绘图器读取已经计算或观测的数据，不自动重新拟合模型、推算缺失观测或生成后验样本。图类型的具体字段由 recipe 列表确定。

## 文件与字段

- 接受 UTF-8 JSON、CSV、TSV、ECSV，单文件上限 200 MiB；不接受 pickle 或对象归档。JSON 根节点必须是对象，重复键、非标准 NaN/Infinity 或溢出的浮点数会报错；缺测可写 `null`。
- CSV/TSV 第一行是唯一且非空的列名。空单元格保留为缺测，数值列中的 NaN 供 recipe 显示断点或明确排除；不会自动连线补值。重复列名与字段数不齐的记录被拒绝。
- ECSV 经 Astropy 读取，列单位和表格元数据进入来源记录，掩码保持为缺测。绘图前仍应确认所选字段的单位一致。
- 数据字典中的 `_source` 为保留字段，记录绝对路径、源文件 SHA-256、字节数和格式；表格还记录列名、行数及可取得的单位。原始输入不会被改写。
- 普通 CSV/TSV 不包含可靠的单位、历元或时间尺度约定。`bjd`、`time_day` 等列名不能单独证明 BJD_TDB、HJD_UTC 或其他时间约定；应依据数据说明声明并保留原坐标。

`load_data(path)` 返回原始字段加 `_source`。`apply_mapping(data, {"x": "time", "y": "flux"})` 增加字段别名并记录映射，不删除原字段、不换算单位、不覆盖现有同名字段。CLI 使用规格 JSON 的 `mapping` 字段提供同样的显式映射，例如 `"mapping": {"x": "time", "y": "flux"}`。

## 径向速度表的通用适配

结果目录中同时存在训练、内部验证、独立留出、合成实验和真实观测，选用时需明确其角色。不能把合成恢复实验图标成真实观测图，也不能把反复参与选择的数据标成独立验证。

一种可直接适配的径向速度表格式如下，列名由数据提供者明确约定：

| 列 | 含义 |
| --- | --- |
| `bjd` | 源结果使用的 BJD 时间坐标，具体时间尺度需查原数据协议 |
| `star` | 恒星标签 `aa`、`ab` 或 `b` |
| `observed_km_s` | 已有观测径向速度 |
| `sigma_km_s` | 源文件提供的观测不确定度 |
| `predicted_km_s` | 已有模型的留出预测 |

画每颗恒星的径向速度及残差时，先按 `star` 分组，避免将不同恒星连接为一条曲线。数值单位为 km/s，原有时间值照录；残差的正负约定应在图注声明。

`load_stellar_rv(path, star="aa")` 对上述已知格式提供显式适配，返回 `x`/`t`、`observed`、`model`、`sigma` 和来源记录。它也支持 `time_day`、`quoted_sigma_km_s` 及 `fitted_km_s` 这些显式列名。一个文件包含多个 `candidate` 时必须指定 `candidate`；选择行号和字段映射会保存下来。该适配器不推断星体标签、不求轨道相位、不核实时间尺度，也不把预测不确定度替换成观测误差。

观测误差、预测误差与参数均值误差语义不同，不应互相替代。天测误差还可能含 East/North 协方差；两个单独误差棒不能完整表达相关性。

`inspect_project_results(model_version_directory)` 只浅层列出该版本 `results/`、`validation/` 的文件及其直接子目录，默认最多 200 个，不会遍历整个项目或从文件名自动认定物理含义。
